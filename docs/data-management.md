# 客户数据与迁移

管理页新增“数据管理”。删除和导出前，在运行总览点击“停止”，等待接待完全结束。仅暂停时仍可能有模型任务，因此不能执行这些操作。

## 删除

在“客户会话”选择客户：

- **清空聊天**：保留客户，删除该客户的聊天、需求字段、草稿、待办和 LangGraph 流程记忆，恢复为可接待状态。
- **删除客户**：同时删除客户条目及上述关联记录。

“数据管理”还提供“删除全部客户与聊天”，包含所有店铺的本地记录、流程记忆和运行事件。知识、模型连接、接待设置保留。每次删除需要在页面输入“删除”确认。全部删除会同时清除“已删除消息”屏蔽记录，因此开始接待后可以重新读取客户端列表中的会话；单客户删除仍会屏蔽其旧消息，避免删除后立即复活。

删除只影响本地副本，不操作客户端中的平台历史。数据库保留已删除消息的散列标记，不保存其正文，用于阻止相同消息再次导入。新消息仍可进入接待流程。这个标记只覆盖已同步过的消息，不能代表平台全部历史已经删除。

删除不会清理此前导出的 ZIP、外部评估文件或备份；如需清理这些副本，请另行处理。

## 导出

点击“下载迁移包”，通过 SQLite 快照生成 ZIP，支持当前最多 512 MB 的解压数据：

| 文件 | 内容 |
| --- | --- |
| `business.sqlite3` | 客户、消息、草稿、待办、配置、知识、原始知识材料、删除去重标记 |
| `checkpoints.sqlite3` | 流程等待进度（存在时导出） |
| `manifest.json` | 格式版本、生成时间、密钥选项和文件 SHA-256 校验值 |

默认清除导出副本中的模型 API Key、Linkr Token、飞书 Webhook 和签名密钥，并关闭该副本的飞书通知。勾选“包含模型密钥、Linkr Token 和飞书凭据”则保留这些配置；ZIP 本身没有加密。原工作空间中的密钥不受影响。版本 1 的旧迁移包（包含 `mock.json`）仍可恢复，其中的模拟记录会被忽略。

导出包始终包含客户资料。客户端登录状态、项目代码、`.env`、原始 CSV 和知识整理包文件不包含在内；已经导入数据库的知识与原始材料仍完整保留。

## 恢复到新机器或新目录

在目标机器安装项目依赖，将导出的 ZIP 复制过去，在项目根目录执行：

```powershell
.\run.cmd restore-data "C:\Downloads\cs-duty-workspace.zip" --data-dir "artifacts\restored"
.\run.cmd serve --data-dir "artifacts\restored"
```

恢复只接受尚不存在的目标目录，不覆盖旧数据。程序检查包版本、文件清单、哈希及数据库完整性，检查通过后才发布目标目录。恢复不会自动开始接待，也不会连接客户端或模型。

未携带凭据时，重新填写模型密钥、Linkr Token 和飞书配置；客户端登录状态不受影响（登录在客户端自身维护）。确认数据与 Linkr 连接后再开始接待。尚未完成处理的待办和流程会保留；发送结果不明的状态仍需人工核对。使用与导出端相同或兼容的项目版本恢复。

需要回到旧工作空间时，先停止当前服务，再使用原 `--data-dir` 路径启动。超过大小上限时，可完全停止原服务后复制整个数据目录进行迁移。
