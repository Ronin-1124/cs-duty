# 飞书协作

接待设置支持两种机器人：自定义机器人通过 Webhook 单向通知；企业自建应用机器人通过飞书长连接接收处理结果，不需要公网回调地址。两者保留为独立配置，按选定方式运行。

## 首次配置

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，添加机器人能力。配置应用可用范围，首轮测试可只包含本人。
2. 为应用申请发送机器人消息、接收群聊中 @机器人的消息权限；需要私聊时再增加接收用户发给机器人的单聊消息权限。订阅 `im.message.receive_v1` 事件，接收方式选“使用长连接接收事件”。后台可能要求先建立长连接才能保存，此时先做下一步。
3. 在本地“接待设置 → 飞书协作”选择“应用机器人 · 双向协作”，填写 App ID / App Secret，暂不启用待办协作，保存。点击“连接飞书”。将所需权限、事件和机器人能力发布到应用版本，并完成企业要求的审核。
4. 打开机器人私聊，或将机器人添加到指定群聊。在本地点击“识别本人和会话”，把显示的绑定命令发给机器人（群内需 @机器人）。绑定码 5 分钟内有效，只能使用一次；它只发现 ID，不自动开放权限。
5. 核对识别的用户 ID 和会话 ID，点击“填入白名单和通知会话”。首轮只保留本人一条用户 ID。断开飞书连接，勾选“启用待办协作”，保存后重新连接。私聊测试同时勾选允许白名单私聊；群聊无需该选项。
6. 点击“发送测试通知”，检查目标会话收到不含客户资料的测试消息。随后开始接待，使用模拟客户测试完整待办闭环。

应用密钥保存在当前工作空间 `business.sqlite3` 中，管理页不会回显，空值保存保留旧密钥；不改 `.env`。默认导出会移除应用密钥并关闭通知。只有主动勾选包含凭据的迁移包才保留密钥。

## 处理待办

应用通知包含客户、店铺、需求及短待办编号。群内回复该待办并 @机器人填写已确认结果，或发 `@机器人 处理 <8 位待办编号> <确认结果>`；私聊直接发处理命令即可。群聊中的普通消息可能不在事件订阅范围内，因此务必 @机器人。

接收端同时核对员工 `open_id` 和会话 `chat_id`，私聊另需启用开关。群内处理命令只能对应发到本群、由当前应用通知过的待办；短编号存在歧义时不处理。未知员工、未允许的会话、机器人消息、非文字、普通聊天及已处理待办均忽略，不调用模型。

有效结果和飞书消息 ID 在同一数据库事务中保存，重复事件不会覆盖第一次结果。应用会发送保存确认。若 RPA 未运行，结果保持“排队中”；开始接待后由原有 LangGraph 流程继续处理，遵循填写草稿／自动发送、客户接管和新消息校验。

## 联机自检

真实凭据保存后，可以先用命令行验证，不必启动接待或打开浏览器：

```powershell
.\run.cmd feishu-check              # 校验应用凭据并读取机器人 open_id
.\run.cmd feishu-check --connect    # 再建立长连接并等待最多 20 秒确认
.\run.cmd feishu-check --send       # 再向已保存的通知会话发送测试消息
```

自检读取数据目录中已保存的配置（默认 `artifacts/app`），不输出密钥；失败时返回非零退出码，并说明是凭据、权限还是网络问题。`--connect` 可以验证开发者后台“使用长连接接收事件”的订阅是否生效。

## 运行与限制

- 飞书连接与 RPA 接待分别启停；服务重启后手动连接飞书、开始接待。飞书暂时断网由 SDK 尝试重连。
- 修改接待设置、清理客户或导出前，停止接待并断开飞书；退出整个服务时会关闭接收子进程。
- 接收使用官方 `lark-oapi` SDK，运行于应用拥有的本地子进程；凭据通过标准输入传递，不放进进程参数。SDK 的原始日志不输出，以免泄露连接凭据或消息内容。
- 待办通知只有在接待运行且飞书已连接时发送。通知结果不明时标记“待核对”，不自动重发。失败重试界面、任务分配、普通群聊问答和卡片交互尚未实现。
- 删除本地客户或聊天会清理关联的飞书消息映射、回调去重记录；不会删除飞书服务器中的已发送消息。
- 本地管理页控制端具有配置权限。白名单限制飞书员工消息，不替代本机访问控制。

参考：[飞书官方 Python SDK](https://github.com/larksuite/oapi-sdk-python)。实际可用权限和发布步骤以租户开发者后台为准。
